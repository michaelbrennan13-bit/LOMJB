# Templates — Firm Precedent Library

Reusable skeletons of the firm's best work product. This library grows with every matter: a good draft, once stripped of client-specific facts, becomes precedent the next matter starts from.

## How a document graduates from `drafts/` to `templates/`

1. **It proves itself.** A demand, letter, or memo works — Michael sent it, it landed, it's the shape you want to reuse.
2. **Strip it.** Remove every client-specific fact: names, dates, figures, injuries, claim numbers, anything identifying. Replace with clear placeholders — `<client>`, `<incident date>`, `<policy limits>`, `<provider>`.
3. **Keep the structure and the language.** The value is the skeleton and the phrasing that worked — the liability-narrative flow, the Stowers checklist, the plain-English openings. Keep the `[VERIFY]` markers on any legal citation; a template never launders an unverified cite into a "safe" one.
4. **Name it by type**, not by matter: `demand-trucking.md`, `engagement-contingency.md`, `records-request.md`, `lien-reduction.md`.
5. **Save it here.** The `demand-letter` and `correspondence` skills end by asking whether to generalize — this is where "yes" lands.

## Rules

- **No client data in `templates/`.** This is the un-privileged, reusable layer. If you can identify a client from a template, it's not stripped yet.
- **Citations stay honest.** `[VERIFY]` markers travel with the template so no one mistakes precedent for verified law.
- **Templates are starting points, not final documents.** Every use gets re-checked against the current matter's facts and current law.
